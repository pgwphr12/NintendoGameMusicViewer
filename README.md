# Nintendo Game Music Viewer · V1.3 (1.3.0)

Windows용 게임 음악 플레이어와 실제 채널별 오실로스코프 뷰어입니다. 새 C++17 멀티파일 프로젝트이며 Mesen/MesenCE/기존 NTSC 프로그램의 코드를 사용하지 않습니다. 게임 ROM이나 게임 화면을 실행하는 기능은 없습니다. NSF/NSFE/SPC/GBS 음악 코어에는 음악 명령을 실행하기 위한 내부 하드웨어 모사가 들어 있습니다.

## 실행

Windows 10/11 x64에서 ZIP 전체를 압축 해제하고 `NintendoGameMusicViewer.exe`를 실행합니다. `gme.dll`을 실행 파일과 같은 폴더에 두세요. .NET, Python, FFmpeg, Visual Studio, CMake는 실행에 필요 없습니다. 오디오 장치가 필요합니다.

파일 열기 또는 끌어 놓기로 NSF/NSFE/SPC/GBS/GSF/2SF/USF/BCSTM/BCWAV/VGM/VGZ를 엽니다. Tracks 버튼으로 내부 트랙을 고릅니다. 이름이 제공되지 않은 곡은 Track 번호로 표시합니다. 파일은 확장자가 아니라 헤더로 식별합니다.

| 기능 | 사용 |
|---|---|
| 열기 | 파일 열기 / Ctrl+O / drag & drop |
| 재생·일시정지 | 버튼 / Space |
| 정지 | 정지 버튼, 위치 0으로 초기화 |
| 이전·다음 곡 | 버튼 / 좌우 화살표 |
| 반복 | 반복 버튼; 길이가 기록된 곡의 끝에서 현재 곡 다시 재생 |
| 트랙 목록 | 곡 선택 버튼 |
| 진행·총 시간 | 메타데이터 길이가 있을 때만 총 시간과 클릭 가능한 진행바 표시 |
| master volume | 기본 100%, 오른쪽 위 슬라이더 및 ±5% 버튼 (F9에서도 사용) |
| 채널 mute | 채널 이름 영역 클릭 |
| 채널 volume | 채널 이름 아래 슬라이더 및 ±5% 버튼 |
| 녹화용 화면 | F9, 재생 조작부 숨김/복원; 음량 조절 유지 |

| 시간축 | + / - 키, 256~4096 samples |

기본 client 크기는 1280×720입니다. 1920×1080 기준으로 16:9를 유지하고 임의 크기에서는 여백을 둡니다. 파형은 검은 계열 배경의 독립적인 가로 lane으로 표시합니다. F9와 F11을 함께 사용하면 외부 녹화에 적합합니다. 내장 영상 녹화는 없습니다.

## 실제 지원과 파형의 의미

- NSF / NSFE: PULSE 1, PULSE 2, TRIANGLE, NOISE, DMC. 코어가 지원하는 확장음은 추가 채널로 표시합니다. FDS는 FDS입니다.
- SPC: 채널 1~8 (녹화뷰: CHANNEL 1~8).
- GBS: SQUARE 1, SQUARE 2, WAVE, NOISE.
- 게임 ROM, MP3/MP4 분석 및 3SF 파일은 지원하지 않습니다. 예시 MP4는 화면 연구 자료이며 음악 코어 입력 파일이 아닙니다.

같은 음악을 동일한 48kHz 시간축의 독립적인 libgme 인스턴스에서 렌더링하고, 각 인스턴스의 다른 voice를 모두 mute합니다. 따라서 파형은 실제 해당 하드웨어 voice만 활성화한 PCM입니다. 최종 믹스의 FFT·채널 추측·복제·random 파형을 사용하지 않습니다. 자동 초기 무음 건너뛰기를 끄므로 서로 다른 voice가 같은 시간축에 남습니다.

표시 신호는 코어의 오디오 필터를 지난 pre-fader 신호이며 raw DAC/레지스터 상태는 아닙니다. 불필요한 ACTIVE/SILENT 글씨는 표시하지 않습니다. mute해도 원본 채널 파형은 유지되어 어떤 채널을 끈 것인지 볼 수 있습니다. DC는 화면에서만 제거하고 min/max envelope와 rising trigger로 안정된 파형을 그립니다. 자동 표시 gain은 청취 볼륨을 바꾸지 않습니다.

개별 채널 volume이 모두 100%이면 원래 믹스를 사용하고 mute는 코어의 실제 mute API에 반영합니다. 개별 volume을 바꾸면 분리 PCM을 합산합니다. 이때 NES 비선형 믹서와 공유 효과의 채널 간 상호작용까지 원래 믹스와 완전히 같지는 않을 수 있습니다. 파형을 얻기 위한 voice별 코어 때문에 파일/확장음에 따라 CPU와 메모리 사용량이 큽니다. 모든 음악 덤프와 특수 코어 동작을 보장하지 않습니다.

## 시간축·오디오 안정성

음악 생성 워커 → 고정 48kHz → bounded SPSC audio ring → 장치 출력 콜백 → 출력 레이트용 32-tap windowed-sinc resampling. 장치 출력 콜백은 파일 읽기, 음악 코어 실행, UI 갱신이나 메모리 할당을 하지 않습니다.

채널 데이터 → 각각의 history ring → 실제 소비한 내부 샘플 시각 → 약 60Hz UI. 재생 중 잠깐 데이터가 부족하더라도 history를 지우지 않습니다. underrun 횟수는 내부 진단 정보로 유지합니다. 장치 출력의 실제 지연 때문에 파형과 물리적 스피커 출력 사이에 작은 차이가 있을 수 있습니다.

출력 레이트 변경 시 기존 장치가 열린 상태에서 새 출력 장치를 준비합니다. 성공하면 음악 코어, 재생 위치, 채널 history를 유지해 교체합니다. 동시 두 장치 열기를 지원하지 않는 드라이버에서는 잠깐 출력을 닫고 같은 위치에서 다시 엽니다. 새 설정으로 열지 못하면 이전 설정으로 복구하고 오류를 표시합니다. 장치 전환의 짧은 하드웨어 지연이나 모든 OS 장치 조합의 무중단 재생을 보장하지 않습니다. 실제 기본 장치 제거/OS 기본 장치 변경의 자동 재연결은 향후 작업입니다. 출력 변환은 32-tap windowed-sinc 보간과 낮은 레이트용 저역 통과 필터를 사용합니다. 원본 PCM의 정보량을 복원하는 기능은 아닙니다.

파일/곡 전환과 seek는 큐를 초기화합니다. 긴 seek는 각 코어가 음악을 건너뛰어 계산하므로 시간이 걸릴 수 있습니다. 길이가 없는 NSF/GBS 등은 총 시간을 추측하지 않고 `--:--`로 표시하며 수동 정지할 때까지 계속 재생합니다. 따라서 길이를 모르는 음악의 자동 다음 곡/끝 검출은 제공하지 않습니다. 별도 검색·파일 라이브러리와 채널 주파수/레지스터 표시도 아직 구현하지 않았습니다.

## GitHub Actions / 빌드

source ZIP에서 압축 해제한 소스 폴더 전체를 새 GitHub 저장소 루트에 올립니다. `.github/workflows/windows.yml`은 Windows 2022 runner의 VS2022·CMake·Python 도구를 사용해 configure → build → 실제 코어/콜백 CTest → install → ZIP artifact를 생성합니다. 별도 로컬 도구 설치 없이 Actions의 `NintendoGameMusicViewer-Windows-x64` artifact를 받으세요. 이 워크플로는 준비된 구성으로 제공하며 실제 GitHub 실행은 저장소에 올린 뒤 확인해야 합니다.

의존성 upstream source ZIP을 버전·SHA256으로 고정해 third_party에 포함합니다. `latest`나 시스템 libgme 설치에 의존하지 않습니다. 로컬 소스 빌드를 원하는 경우에만 VS2022 C++ 개발 도구, CMake 3.24 이상, Python 3을 사용합니다:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --component Runtime --prefix dist/NintendoGameMusicViewer
```

tests/make_fixtures.py는 상용 곡/게임 ROM이 없는 자체 제작 음악 명령 파일을 생성합니다. tests/Tests.cpp는 실제 포맷 열기, 트랙 전환, 비정상 파일, 채널 독립성, FDS, 실제 PCM 에너지, mute, 48kHz 생성, 44.1/48/96kHz 출력, rate change, SPSC stress, envelope, pause/resume/seek/stop/끝 재생을 검사합니다. CI의 SDL dummy audio driver는 소리를 재생하지 않지만 실제 callback 경로를 실행합니다. 실제 장치와 상용 음악 파일의 수동 확인 범위는 VALIDATION.md를 참고하세요.

프로젝트 구조와 설계는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 의존성·라이선스는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)입니다. 프로그램은 GPL-2.0-or-later로 배포하며 전체 소스를 포함합니다. LICENSE를 참조하세요. libgme는 LGPL DLL이며 교체 가능하도록 별도 파일로 제공합니다. SDL2와 libgme의 원본 소스·라이선스를 포함합니다.

## V1.1 변경

일반 화면의 조작부와 채널 표시는 한국어이며, F9 녹화 화면에서는 채널 표시와 음소거 표시가 영어로 전환됩니다. 기본 트랙 이름은 두 화면 모두 Track으로 표시합니다. 실제 곡 제목/제작자 등 파일 메타데이터는 원문을 유지합니다. 화면 안의 프로그램 제목/버전은 제거했습니다. 단축키 안내는 일반 화면 하단에만 표시하고 녹화 화면에서는 숨깁니다. 채널 이름 클릭 음소거와 슬라이더 음량 조절은 유지합니다. 음소거하면 파형은 회색으로 남고 일반 화면은 음소거, 녹화 화면은 MUTED가 표시됩니다. F9 녹화 화면에서는 기존과 같이 조작을 숨깁니다.

전체 화면에서 그림 버퍼를 매 프레임 새로 만들던 처리를 없앴습니다. 창 크기가 바뀔 때만 실제 출력 크기의 32-bit DIB를 생성하고, 글꼴/펜/브러시를 재사용합니다. 파형의 min/max와 연결선을 버퍼에 직접 그려 수천 번의 GDI 호출을 제거했습니다. 4K도 실제 4K 버퍼를 사용하며 출력 해상도나 음악 샘플 수를 낮추지 않습니다. 측정 방법과 한계는 docs/PERFORMANCE.md에 있습니다.

FDS가 포함된 NSF/NSFE는 전체 출력에 +4 dB, SPC(SNES)는 +10 dB의 기본 보정을 적용합니다. 일반 NES/GBS는 기본 보정을 바꾸지 않습니다. 스테레오 공통 peak limiter(상한 0.98, 즉시 attack / 150 ms release)를 master volume 앞에 적용해 보정 때문에 출력 범위를 넘지 않도록 합니다. 조용한 부분이나 무음을 자동으로 키우는 정규화는 아닙니다. 채널 파형은 보정 전 실제 PCM이며 개별 mute/volume과 master 조절은 그대로 사용할 수 있습니다. 실제 음악 덤프와 장치에 따라 체감 음량은 다르므로 MASTER로 조절하세요.

## 특수칩 호환 범위

현재 묶인 libgme 0.6.5 NSF/NSFE 코어에는 VRC6, VRC7, FDS, MMC5, Namco 163(106), Sunsoft 5B(FME-7) 구현이 있습니다. 모든 특수칩/파일/드라이버의 완전 호환을 의미하지 않습니다. 새 파일 버전/추가 기능이나 특수 뱅크 전환 등에 대한 호환성은 실제 파일로 확인해야 합니다. 현재 별도 실음 테스트가 있는 확장음은 FDS이며 나머지 칩의 실제 곡 검증을 완료했다고 주장하지 않습니다. SNES는 SPC 상태 덤프 재생이며 게임 ROM의 모든 보조칩을 실행하는 기능이 아닙니다.


## V1.3 변경

- Doki Doki Panic FDS(36 tracks)와 Zelda II FDS(45 tracks)의 $6000 load 오류 수정. FDS $6000–$DFFF RAM 읽기/쓰기/실행, $5FF6–$5FFD bank-copy 처리를 추가합니다. 원본 ZIP은 유지하고 CMake가 LGPL 수정 소스 3개를 적용합니다. docs/FDS-COMPATIBILITY.md를 참고하세요.
- 채널 음량은 0–200%입니다. 기본값은 100%, 슬라이더 중간이 100%, 오른쪽 끝이 200%입니다. 삼각파/노이즈/DMC/FDS 웨이브가 작은 곡에서는 해당 채널의 슬라이더만 올리면 됩니다. 펄스 등 기본 밸런스를 자동으로 바꾸지 않습니다.
- 피치/속도를 0.1배 단위로 0.5–2.0배 조절합니다. 초기화는 1.0배입니다. 피치와 속도가 함께 바뀌며 피치를 유지하는 타임 스트레치는 아닙니다. 재생 위치는 원본 음악 시각입니다. 녹화 화면에서는 조작부를 숨깁니다.
- 기본 출력은 96kHz이며 16/22.05/32/44.1/48kHz도 선택할 수 있습니다. 내부 생성은 48kHz이고 출력 때 변환합니다. V1.2부터 출력 변환은 windowed-sinc 필터로 고주파 aliasing을 억제합니다.
- 반향 버튼으로 약한 리버브를 켜고 끕니다(기본 꺼짐). 원음에 추가하는 감쇠된 반사음이며 원본 SPC 자체의 echo를 제거하지 않습니다. 파형은 효과 전 신호입니다. 최종 limiter가 출력 피크를 제한합니다. stop/seek/Track 변경 때 추가 잔향을 초기화합니다.

NES에서 DMC는 실제 isolated PCM이 감지되기 전까지 숨깁니다. 사용되면 현재 트랙에서 계속 표시합니다. 새 파일/다른 Track을 열 때 감지 상태를 초기화하고, 같은 트랙의 seek/stop에서는 유지합니다. 매우 작은 신호(peak 0.0001 이하)는 미사용으로 간주할 수 있습니다. 오디오 채널 자체를 제거하는 기능은 아니며 재생/음소거/volume은 원래 core index에 연결됩니다.

## V1.4 변경 사항

- 피치/속도 조절 단위는 0.10배와 0.01배 중 선택합니다. 두 자리로 표시하며 단위를 바꿔도 미세 조절값을 유지합니다.
- 반향의 추가 반사음 비율을 0.18에서 0.45로 높였습니다. 기본 꺼짐이며 켜고 끌 때 부드럽게 전환합니다.
- 전체/개별 채널 음량에 ±5% 버튼을 추가했습니다. 슬라이더도 유지합니다. F9 녹화뷰에서도 전체/채널 음량과 클릭 음소거를 조절할 수 있습니다. 녹화뷰의 볼륨 조작부는 영상에 표시됩니다.
- FDS 채널명은 두 화면 모두 FDS입니다. SNES는 일반 화면에서 채널 1~8, 녹화뷰에서 CHANNEL 1~8로 표시합니다.

## V1.5 변경 사항

반향 강도는 0~100% 슬라이더와 ±5% 버튼으로 조절합니다. 기본값은 V1.4와 같은 45%이며, 켜기·끄기는 별도로 유지합니다. 0%는 추가 반사음이 없고 100%는 원음에 반사음을 1배 더하는 설정입니다. 숫자는 잔향 길이가 아니라 추가 반사음의 크기입니다. 변경 시 부드럽게 전환하며 출력 limiter가 피크를 제한합니다.

F9 녹화뷰에서는 전체 음량만 조절할 수 있습니다. 채널별 슬라이더, ± 버튼, 음량 퍼센트는 숨깁니다. 채널 이름 클릭 음소거와 MUTED 표시는 유지합니다. 일반 화면에서는 모든 채널별 음량 조절이 가능합니다.

## 정식 V1 · 1.0.0

이 패키지가 정식 V1입니다. 이전 V1.1~V1.5 표기는 개발 중 배포본 기록입니다. 기본 전체 음량은 100%입니다.

반향에는 소리가 끝난 뒤에도 울림이 남는 잔향을 추가했습니다. `잔향 시간`의 ± 버튼으로 0.1~3.0초 범위에서 0.1초씩 조절하며 기본값은 1.2초입니다. 이는 저주파 잔향이 약 60dB 감쇠하는 기준 시간이며 실제로 들리는 길이는 음색·강도·재생 환경에 따라 달라집니다. `반향 강도`는 울림의 크기(0~100%, 기본 45%)이며 시간과 별도로 조절합니다. 반향은 기본 꺼짐입니다. 음표가 끝난 뒤에는 잔향이 이어지고, 정지·탐색·트랙 전환 시에는 잔향을 초기화합니다.

녹화뷰는 전체 음량만 표시하고 채널별 음량 조작부는 숨깁니다. 채널 클릭 음소거는 유지합니다.

## V1 지원 확장판 · 1.0.1

| 기종 | 지원 음악 포맷 | 파형의 의미 |
|---|---|---|
| NES / Famicom | NSF, NSFE | 기본·확장 하드웨어 채널 |
| SNES | SPC | 8개 DSP 보이스 |
| Game Boy | GBS | 4개 하드웨어 채널 |
| Game Boy Advance | GSF, miniGSF | 펄스 1/2, 웨이브, 노이즈, PCM A/B |
| Nintendo DS | 2SF, mini2SF | 16개 하드웨어 오디오 채널, 두 열 표시 |
| Nintendo 64 | USF, miniUSF | 지원되는 Audio/NAudio 합성 슬롯 + 게임 잔향/기타; 다른 방식은 좌우 출력 |
| Nintendo 3DS | BCSTM, BCWAV | 파일에 저장된 오디오 채널 |
| Sega Master System | VGM, VGZ | PSG 4채널, YM2413 확장 사용 시 18채널 |
| Mega Drive / Genesis | VGM, VGZ | FM 6채널, DAC, PSG 4채널 |

miniGSF/mini2SF/miniUSF는 `_lib`, `_lib2` 등으로 지정한 gsflib/2sflib/usflib 파일이 필요합니다. 원래 폴더 구조를 유지하세요. 라이브러리 파일 자체는 트랙으로 열지 않습니다. PSF 계열은 파일 하나가 트랙 하나이며 제목·게임·작곡자·length/fade 태그를 읽습니다. 다른 곡은 다른 음악 파일을 여세요. 파일 형식은 확장자가 아니라 헤더로 검사하지만 3DS 스트림은 디코더의 파일명 검사를 위해 원래 확장자도 유지해야 합니다. PSF 체인과 압축 데이터에 범위·CRC·순환 참조 검사가 적용됩니다.

GBA는 원래 믹스와 6개의 분리 코어를 같은 48kHz 시각에서 실행합니다. PCM A/B 안에 소프트웨어로 합쳐진 악기까지 분리하지 않습니다. DS는 하나의 코어에서 실제 16채널 신호를 UI 음소거와 최종 클리핑 전에 추출합니다. DS의 44.1kHz와 USF/3DS의 원래 레이트는 같은 시각의 선형 보간으로 48kHz에 맞춥니다.

N64는 지원되는 Audio/NAudio 방식의 실제 envelope 합성 슬롯을 추출합니다. 슬롯은 MIDI 악기 이름이나 고정 하드웨어 채널을 뜻하지 않습니다. 게임 잔향과 추출되지 않은 성분은 별도 항목으로 유지합니다. 3DS는 파일에 저장된 오디오 채널이며 악기·노트별 신호가 아닙니다. BCSTM/BCWAV는 PCM/DSP-ADPCM 등 vgmstream의 내장 디코더를 사용하며 외부 FFmpeg/Vorbis/MP3 코덱은 빌드하지 않습니다. 3DS 게임 ROM, BCSAR 아카이브·BCSEQ 시퀀스·3SF 재생은 지원하지 않습니다. 이 표는 기종별 음악 파일 지원을 뜻하며 해당 기종의 모든 덤프·음악 드라이버·코덱 호환성을 보장하지 않습니다.

자체 제작 ARM/MIPS 음악 드라이버 및 PCM/DSP-ADPCM 스트림으로 재생·분리·음소거·탐색·태그·끝·오디오 장치·화면을 검증했습니다. V1.2에서 사용자 폴더의 N64 38개·3DS 99개·GBA 3개 파일의 첫 6초 및 탐색·음소거를 검증했습니다. 모든 구간과 모든 게임을 검증한 것은 아닙니다. DS 사용자 음악 검증은 아래 V1.1 기록을 참조하세요. 전체 소스 및 고정된 원본 코어는 별도 source ZIP에 포함합니다. 실행 ZIP과 source ZIP을 함께 제공하세요.

## V1.1 안정성 및 폴더 재생

DS의 일회성 PCM/ADPCM 채널이 끝날 때 파형 캡처 범위를 넘어서 기록하던 문제를 수정했습니다. 사용자 New Super Mario Bros. (EMU) 폴더의 98 mini2SF에서 첫 6초, 탐색, 전체 음소거를 메모리 검사로 확인했습니다. 모든 음악의 전체 구간을 검증했다는 뜻은 아닙니다. docs/DS-STABILITY.md를 참조하세요.

SPC, GSF/miniGSF, 2SF/mini2SF, USF/miniUSF, BCSTM/BCWAV는 현재 파일과 같은 폴더의 같은 기종 음악을 파일명의 숫자 순서로 정렬합니다. Tracks 메뉴, 이전/다음 버튼, 좌우 키는 폴더 파일을 선택합니다. 하위 폴더와 gsflib/2sflib/usflib는 목록에서 제외합니다. 재생 중 수동 전환은 재생을 유지하고, 일시정지 중 전환은 일시정지를 유지합니다.

길이가 있는 트랙이 끝나면 다음 파일을 자동 재생하며, 마지막 파일에서는 정지합니다. 수동 이전/다음은 폴더의 처음과 끝을 순환합니다. 반복을 켜면 현재 트랙을 반복합니다. 길이 태그가 없는 PSF 음악은 끝을 알 수 없어 수동으로 다음 파일을 선택해야 합니다. NSF/NSFE/GBS는 파일 내부 트랙 선택을 유지합니다.

## 자동재생 켜기·끄기 (1.2.0)

일반 화면의 `자동재생 켜짐/꺼짐` 버튼 또는 `A` 키로 폴더의 다음 파일 자동 재생을 전환합니다. 기본은 켜짐입니다. 끄면 현재 트랙 종료 후 멈추며, 수동 이전/다음과 Tracks 선택은 계속 사용할 수 있습니다. 설정은 파일을 바꾸거나 녹화뷰로 전환해도 유지되며, 프로그램을 다시 실행하면 기본값으로 시작합니다. 녹화뷰에는 버튼을 표시하지 않으며 A 키로 전환할 수 있습니다. 반복은 현재 트랙을 반복하는 별도 설정입니다. 자동재생을 켜는 동작만으로 정지한 음악을 다시 시작하지는 않습니다.

## V1.2 · 1.2.0

- GBA PCM: 게임 타이머의 실제 샘플 속도에 맞춘 16개 재구성 필터로 기존 3단계 필터를 교체했습니다. 최종 출력의 선형 보간을 32-tap windowed-sinc로 개선하고 낮은 출력 레이트·고속 재생의 aliasing을 억제했습니다.
- 제공된 Super Mario Advance 4의 PCM은 약 10,512 Hz·8비트입니다. 96kHz 출력으로 원본에서 사라진 고음 정보를 복원할 수 없습니다. PCM A/B에 이미 합쳐진 악기는 별도로 분리하지 않습니다.
- N64: Audio/NAudio envelope의 실제 dry 합성 슬롯을 분리하고, 같은 interleave/save/Audio Interface DMA 시각을 추적합니다. 최대 30개 슬롯 및 게임 잔향/기타를 지원하며 V1.3에서는 사용 여부와 관계없이 모든 슬롯을 처음부터 화면에 표시합니다. 별도 코어 30개를 실행하거나 최종 믹스를 복제하지 않습니다. 지원되지 않는 NEAD/MusyX/소프트웨어 믹스 방식은 좌우 출력으로 남습니다.
- 3DS: BCSTM track table의 stereo/mono 묶음·음량·팬을 읽습니다. 다채널 스트림의 단일 mono stem을 양쪽에 배치합니다. 원본이 2채널 최종 믹스이면 악기별 분리는 제공되지 않습니다. 예: ATHLETIC 5채널, MENU 8채널, BIG_MARIO 2채널.
- V1.1의 자동재생 토글·폴더 재생·DS 안정성 수정을 유지합니다. 전체 수정 소스와 GPL 배포 조건은 그대로 포함합니다.

## V1.3 · 1.3.0

- SMS 및 메가 드라이브/Genesis의 VGM/VGZ를 추가했습니다. SMS PSG 4채널, YM2413 FM 확장 사용 시 FM 9채널·드럼 5채널·PSG 4채널, 메가 드라이브는 FM 6채널·DAC·PSG 4채널을 표시합니다.
- VGM/VGZ도 폴더 기준 이전·다음·자동재생을 지원합니다. 명령의 실제 대기 시간을 읽어 첫 재생 구간이 끝나면 다음 파일로 이동합니다. 반복 버튼은 파일 처음부터 다시 재생합니다.
- 채널이 9개 이상이면 화면 중앙을 기준으로 왼쪽 위→아래, 오른쪽 위→아래 순서로 모두 표시합니다. N64 슬롯은 소리가 나기 전부터 표시하며 NES의 사용하지 않는 DMC 숨김은 유지합니다.
- 실행 파일과 소스는 별도 ZIP입니다. `NintendoGameMusicViewer-V1.3-Windows-x64.zip`은 실행 파일·DLL·문서·라이선스만 포함하고 `NintendoGameMusicViewer-V1.3-source.zip`에 전체 소스·코어·빌드 파일·테스트가 있습니다. GPL 배포 시 두 ZIP을 함께 제공하세요.

지원 범위는 SMS/메가 드라이브의 단일 SN76489·YM2413·YM2612 및 기존 DAC 명령을 사용하는 VGM/VGZ입니다. 다른 기종 VGM, 이중 칩, VGM streaming DAC 명령(0x90~0x95), GYM/SGC, ROM은 지원하지 않습니다. 압축 전후 파일은 최대 64MiB, 첫 재생 구간은 최대 1시간입니다. GENS FM 코어는 실제 칩과 음색 차이가 있을 수 있습니다. 자세한 구현은 소스 ZIP의 docs/V1.3-SEGA.md에 있습니다.
