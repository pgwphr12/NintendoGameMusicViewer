# Windows integration · V1.3.1

The original waveform/note artwork is in `src/app/resources/viewer.svg`, with PNG and a seven-resolution ICO. `src/app/app.rc` embeds the icon as resource 101. `Window::run` sets both window icon sizes; the EXE icon also supplies Explorer and association icons. `tools/make_icon.py` can regenerate these assets with Pillow; rebuilding the application uses the committed ICO and does not require Pillow.

`src/app/main.cpp` parses `--play` and normal file arguments before acquiring `desktop::InstanceGate`. A named mutex includes the current user's SID and is scoped to the Windows session. A second process locates the primary window by class and instance property and sends an absolute UTF-16 path via `WM_COPYDATA`. The receiving handler copies and validates the payload before acknowledging it, then queues file loading onto its own UI thread. Empty requests only activate the window. A bounded queue, deferred processing during decoder transitions and a bounded handoff wait avoid duplicate players or reentrant decoding. If the primary dies during startup, an abandoned mutex allows a new primary.

`src/app/WindowsIntegration.cpp` centralizes registration, consent and prompt state. Supported extensions match the file chooser: NSF, NSFE, SPC, GBS, GSF/MINIGSF, 2SF/MINI2SF, USF/MINIUSF, BCSTM, BCWAV, VGM/VGZ. Per-user registration writes application capabilities, RegisteredApplications, private ProgIDs with icon/open commands, OpenWithProgids, Applications SupportedTypes and App Paths. It never writes extension default values or Explorer UserChoice. The quoted open command is `"absolute executable path" --play "%1"`.

Consent registers this application and opens `ms-settings:defaultapps?registeredAppUser=NintendoGameMusicViewer`. Windows performs the final default-app selection. Preferences persist the initial registration consent and optional prompt suppression. F10 and the window system menu reopen the prompt; recording mode uses English. Previously consented portable registration refreshes after moving the EXE, without changing Windows default choices. Snapshot mode does not participate in instance forwarding or prompt display. `NGMV_TEST_SESSION` suppresses prompts and separates test instance groups.

Tests: `DesktopTests.cpp`, `ui_default_prompt.py` and `ui_single_instance.py`. Registry tests use an isolated temporary HKCU subtree. Prompt tests redirect HKCU only in their helper process and decline registration, so automated tests do not change real defaults or open Windows Settings. Existing audio, layout, click and playlist tests remain enabled.
